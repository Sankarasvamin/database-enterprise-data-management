# 简化数据库说明

本文档描述 `数据库大作业` 目录中的当前数据库设计。这里的“当前结构”以执行下面两份 SQL 之后的最终结果为准：

1. `简化数据库.sql`
2. `去冗余字段.sql`

也就是说，本文档描述的是去掉冗余名称列、按更规范 join 方式组织后的最终数据库，而不是原始宽表 CSV 的完整列集。

## 数据来源与抽样方式

- 来源目录：`maindata/sql_ready`
- 输出目录：`数据库大作业`
- 随机种子：`20260413`
- 抽样逻辑：以 `transfers.csv` 为中心随机抽取 `600` 条记录，再反推保留相关 `players`、`clubs`、`coaches`
- 维表策略：`country_dim`、`league_dim`、`position_dim`、`player_type_dim` 保留完整清单，因为它们是硬性对照表

## 各表结构与内容

### `country_dim`

- 作用：国家名称清单表，提供统一国家编号
- 主键：`country_dim_id`
- 内容：每一行代表一个国家或地区名称标准项，供球员国籍、俱乐部所属国家、联赛所属国家等字段引用

字段：

```text
country_dim_id, country_name, country_name_normalized
```

### `league_dim`

- 作用：联赛名称清单表
- 主键：`league_dim_id`
- 外键：`country_dim_id -> country_dim.country_dim_id`
- 内容：每一行代表一个联赛，并通过 `country_dim_id` 指向所属国家；最终库中不再重复保留 `country_name`

字段：

```text
league_dim_id, league_name, league_name_normalized, country_dim_id
```

### `position_dim`

- 作用：球员场上位置清单
- 主键：`position_dim_id`
- 内容：例如中场、边锋、门将等位置名称标准项，供 `players` 与 `transfers` 使用

字段：

```text
position_dim_id, position_name, position_name_normalized
```

### `player_type_dim`

- 作用：转会球员类型清单
- 主键：`player_type_dim_id`
- 内容：例如 `Defender`、`Forward`、`Goalkeeper`、`Midfielder` 等类别

字段：

```text
player_type_dim_id, player_type, player_type_normalized
```

### `coaches`

- 作用：教练维表
- 主键：`coach_id`
- 外键：`nationality_country_dim_id -> country_dim.country_dim_id`
- 内容：保存与当前简化库中俱乐部相关联的教练信息，包括基础身份信息与国籍编号

字段：

```text
coach_id, coach_url, short_name, long_name, dob, nationality_country_dim_id, nationality_id, face_url
```

说明：

- `nationality_name` 已删除，因为可通过 `nationality_country_dim_id` join 到 `country_dim` 取得

### `players`

- 作用：球员维表
- 主键：`player_key`
- 外键：
  - `position_dim_id -> position_dim.position_dim_id`
  - `team_country_dim_id -> country_dim.country_dim_id`
  - `team_league_dim_id -> league_dim.league_dim_id`
  - `nationality_country_dim_id -> country_dim.country_dim_id`
- 内容：保存出现在当前转会样本中的球员信息，包括转会统计信息，以及能匹配到的 FIFA 补充信息

字段：

```text
player_key, player_name, player_name_normalized, position_dim_id, age, transfer_record_count, first_transfer_date, last_transfer_date, player_match_status, player_name_match_key, player_id, fifa_version, fifa_update, short_name, long_name, overall, potential, team_id, team_name, team_country_dim_id, team_league_dim_id, nationality_country_dim_id, fifa_update_date, player_source_table
```

说明：

- `position` 已删除，因为可由 `position_dim_id` 连接 `position_dim` 取得
- `team_league_name` 已删除，因为可由 `team_league_dim_id` 连接 `league_dim` 取得
- `nationality_name` 已删除，因为可由 `nationality_country_dim_id` 连接 `country_dim` 取得

### `clubs`

- 作用：俱乐部维表
- 主键：`club_key`
- 外键：
  - `country_dim_id -> country_dim.country_dim_id`
  - `league_dim_id -> league_dim.league_dim_id`
  - `coach_id -> coaches.coach_id`
- 内容：保存转会涉及的俱乐部信息，包括俱乐部标准名、所属国家、所属联赛、转入转出次数，以及匹配到的 FIFA 球队补充信息

字段：

```text
club_key, club_name, club_name_normalized, country_dim_id, league_dim_id, origin_transfer_count, destination_transfer_count, team_match_status, team_id, fifa_version, fifa_update, team_name, coach_id, team_overall, fifa_update_date
```

说明：

- `league_name` 已删除，因为可由 `league_dim_id` 连接 `league_dim` 取得
- `country_name` 已删除，因为可由 `country_dim_id` 连接 `country_dim` 取得
- `team_league_name` 已删除，因为与联赛维表信息重复

### `transfers`

- 作用：转会事实表
- 主键：`transfer_id`
- 外键：
  - `player_key -> players.player_key`
  - `origin_club_key -> clubs.club_key`
  - `destination_club_key -> clubs.club_key`
  - `position_dim_id -> position_dim.position_dim_id`
  - `player_type_dim_id -> player_type_dim.player_type_dim_id`
- 内容：每一行代表一条实际转会记录，保留事实层真正不可由其他表完全替代的信息，例如球员键、转出俱乐部键、转入俱乐部键、金额、日期、空间坐标、周次

字段：

```text
transfer_id, player_key, origin_club_key, destination_club_key, position_dim_id, age, player_market_value, cost, date_of_transfer, destination_latitude, destination_longitude, destination_region, origin_latitude, origin_longitude, origin_region, week_of_transfer, player_type_dim_id
```

说明：

- `player_name` 已删除，因为可通过 `player_key` 连接 `players` 取得
- `origin_club_name`、`destination_club_name` 已删除，因为可通过俱乐部键连接 `clubs` 取得
- `origin_country_dim_id`、`origin_league_dim_id`、`destination_country_dim_id`、`destination_league_dim_id` 已删除，因为这些属性可以通过 `origin_club_key` / `destination_club_key` 连接 `clubs` 再推出
- `origin_country_name`、`origin_league_name`、`destination_country_name`、`destination_league_name` 已删除，因为这些字段在最终库中属于重复描述
- `position` 已删除，因为可通过 `position_dim_id` 连接 `position_dim` 取得
- `player_type` 已删除，因为可通过 `player_type_dim_id` 连接 `player_type_dim` 取得

## 内容理解

- `country_dim`、`league_dim`、`position_dim`、`player_type_dim` 是标准对照表，主要负责减少重复文本
- `players`、`clubs`、`coaches` 是维表，存放实体属性
- `transfers` 是事实表，存放转会事件本身
- 最终设计思路是：事实表尽量只保留自身不可替代的信息，其他名称型和分类型描述通过外键 join 获得

## 导入建议

如果要直接重建最终数据库，推荐执行顺序：

1. `简化数据库.sql`
2. `去冗余字段.sql`

这样导入后的结构与本文档一致。
